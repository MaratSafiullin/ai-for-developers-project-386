# Каркас приложения

**Status:** ready-for-agent

## Problem Statement

Учебный шаг «Каркас приложения» требует рабочую основу без функциональности: бекенд и фронтенд запускаются локально, есть команды тестов и линтера, одна команда прогоняет все проверки локально и в GitHub Actions, коммиты идут по Conventional Commits, в AGENTS.md есть команды и правило про коммиты.

Проект уже создан из Laravel React Starter Kit (Laravel 13, Inertia v3, React 19, TypeScript, Vite+, shadcn/ui, Pest, Pint, Larastan). Большая часть требований закрыта стартер-китом, но:

- стартер-кит несёт авторизацию (Fortify, passkeys, 2FA, настройки профиля), а по условию сервиса авторизации и личных кабинетов нет;
- Laravel Boost генерирует AGENTS.md и skills локально (они в `.gitignore`) и перезаписывает их при каждом `composer update`, поэтому правила, дописанные прямо в AGENTS.md, теряются и в репозиторий не попадают. Проектные правила по задумке Boost живут в закоммиченном `.ai/`, но этот каталог пока не используется;
- в инструкциях агентов нет правила про формат коммитов;
- дымовой тест проверяет только главную страницу, но не health-эндпоинт;
- решение о том, как совместить обязательный клиентский SDK с Inertia, нигде не записано;
- рекомендации шага про mise, hk и pitchfork сознательно отложены и нигде не зафиксированы.

## Solution

Привести стартер-кит к каркасу сервиса бронирования: убрать авторизацию целиком, хранить проектные инструкции агентов в `.ai/`, добавить проверку health-эндпоинта в дымовой тест, добавить правило Conventional Commits в `.ai/guidelines`, записать ADR про гибрид «страницы через Inertia, данные через SDK» и завести отдельный тикет на решение про mise/hk/pitchfork.

Единой командой проверок остаётся существующая `composer ci:check` (Vite+ check, проверка типов TypeScript, Pint, Larastan, Pest). CI остаётся существующим workflow `tests.yml`: push в `main` и pull request. Веток в учебном проекте не будет, поэтому это покрывает каждый push.

## Implementation Decisions

- **Inertia остаётся.** Страницы рендерятся через Inertia, навигация между страницами использует Wayfinder. Данные страницы в будущем получают через клиентский SDK, сгенерированный из контракта TypeSpec → OpenAPI. JSON API и подключение API-маршрутов появятся на шаге контракта, не на этом. Решение фиксируется в ADR 0001.
- **Авторизация удаляется целиком:** Fortify и его сервис-провайдер и конфиг, actions и concerns валидации, контроллеры и запросы настроек, страницы авторизации, настроек и dashboard, связанные React-компоненты, хуки и типы, маршруты настроек и dashboard, модель пользователя, её фабрика и сидер.
- **Зависимости:** удаляются `laravel/fortify`, `@laravel/passkeys`, `input-otp`. Остальные зависимости не меняются.
- **Схема БД:** из базовой миграции пользователей остаётся только таблица сессий. Миграции passkeys и 2FA удаляются. Миграции кеша и очередей не трогаются. Миграции ещё нигде не применены в продакшене, поэтому базовую миграцию правим на месте.
- **Shared Inertia props** больше не содержат данных аутентифицированного пользователя.
- **Boost:** работает как задумано. AGENTS.md, CLAUDE.md, `boost.json`, `.mcp.json` и каталоги агентов остаются в `.gitignore` и генерируются локально через `php artisan boost:install`. `boost:update` остаётся в post-update хуке Composer без изменений. На клоне без `boost.json` он роняет `composer update`; это известно и принято, перед `composer update` нужно выполнить `php artisan boost:install` (тикет 01, wontfix). Проектные правила кладутся в закоммиченный `.ai/guidelines/`, свои skills в `.ai/skills/`. Skill про Fortify исчезает после удаления пакета и локального `boost:update`.
- **Правило коммитов:** одно правило про Conventional Commits в `.ai/guidelines/conventional-commits.md`. AGENTS.md руками не правится, `/init` не запускается.
- **README:** описывает стек, локальный запуск, проверки и то, что инструкции агентов генерируются локально.
- **Единая команда проверок:** `composer ci:check` без изменений.
- **CI:** существующий `tests.yml` без изменений.
- **mise, hk, pitchfork, commit-msg хук:** отложены в отдельный тикет.

## Testing Decisions

- Хороший тест здесь проверяет внешнее поведение по HTTP: приложение загружается и отвечает. Внутреннее устройство не проверяется.
- Шов один: HTTP feature-тесты Pest через тестовый клиент Laravel. Новые швы не вводятся.
- Дымовой тест: `GET` health-эндпоинта (встроенный в Laravel) отвечает 200, `GET` главной страницы отвечает 200.
- Образец: существующий feature-тест главной страницы.
- Тесты авторизации удаляются вместе с функциональностью. Тесты на удаление не пишутся.
- Критерий готовности всего спека: `composer ci:check` зелёный локально и в GitHub Actions.
