# В props только параметры маршрута и настройки, данные через SDK

**Статус:** принято, 2026-10-31

## Контекст

ADR 0001 принял гибрид: страницы рендерит Inertia, данные приходят через SDK к JSON API. Какие данные страница получает через Inertia props, а какие через SDK, там оставлено открытым.

Inertia умеет отдавать странице любые данные как props и отправлять формы без отдельного API. Если пользоваться этим наравне с SDK, у одних и тех же данных будет два источника, а требование про клиентский SDK размоется.

Гость видит время в часовом поясе владельца без пересчёта. Часовой пояс есть в ответе слотов, но во встрече из ответа на бронирование и в списке встреч владельца только ISO-строки со смещением. Без пояса браузер покажет их в своём локальном времени.

## Решение

- **Через props** страница получает только параметры маршрута и настройки приложения из конфига. Часовой пояс владельца приходит общим prop `timezone` из `HandleInertiaRequests::share`.
- **Через SDK** идут все доменные данные (типы встреч, слоты, встречи) и все изменения (создание типа, бронирование).
- Inertia-формы (`useForm`, `<Form>`) и `useHttp` для доменных данных не используются: они обходят SDK.

## Отвергнутые варианты

- **Только параметры маршрута, без настроек.** Неоткуда взять часовой пояс для встреч, время показывается в поясе браузера.
- **Начальные доменные данные через props, SDK для изменений и перезапросов.** Два источника одних и тех же данных, их нужно держать согласованными, а SDK используется лишь частично.

## Последствия

- Веб-маршруты не читают доменные данные из базы: они только выбирают компонент страницы.
- Тест страницы проверяет компонент и props. Поведение данных проверяется на уровне API.
- Страница загружает данные после рендера и показывает состояние загрузки.
